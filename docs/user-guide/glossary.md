# Glossary

## NCBI Databases and Identifiers

**BioProject**
:   An NCBI database entry that groups related biological data (sequences, samples, experiments) under a single project identifier. BioProject accessions start with `PRJNA`.

**BioSample**
:   An NCBI database that stores metadata describing biological source materials. Each BioSample record represents a single specimen or isolate with attributes such as collection date, host, and geographic origin. Accessions start with `SAMN`.

**SRA (Sequence Read Archive)**
:   An NCBI repository for raw sequencing reads (FASTQ files). SRA submissions are linked to BioSample records and contain instrument metadata, library preparation details, and the raw data files.

**GenBank**
:   An NCBI nucleotide sequence database for annotated sequences. GenBank records include the consensus sequence, feature annotations (genes, CDS, proteins), and source metadata. Accessions are alphanumeric (e.g., `OQ123456`).

**SPUID (Submitter-Provided Unique ID)**
:   A unique identifier assigned by the submitter to link records across NCBI databases (BioSample, SRA, GenBank) within a single submission. SPUIDs are scoped to a namespace and must not be reused across submissions.

## File Formats

**SQN (Sequin file)**
:   A binary file in ASN.1 format that contains an annotated sequence ready for GenBank submission. Generated by `table2asn` from a FASTA file, feature table, and submission template. This is the primary submission format for annotated viral sequences.

**FSA (FASTA for table2asn)**
:   A FASTA file prepared with headers formatted for `table2asn`. The sequence identifier in the header must match the corresponding entries in the feature table (.tbl) and source modifiers table (.src).

**SRC (Source modifiers table)**
:   A tab-delimited file containing source modifier information for each sequence (organism name, strain, isolation source, collection date, etc.). Used by `table2asn` to embed source metadata into the SQN file.

**SBT (Submission template file)**
:   A file containing submitter contact information, organization details, and citation data. Generated by [NCBI's template tool](https://submit.ncbi.nlm.nih.gov/genbank/template/submit/) or from `submission_config.yaml` by the pipeline. Required by `table2asn`.

**CMT (Comment file)**
:   A tab-delimited file containing structured comments that are embedded into GenBank records. Structured comments appear in a defined format (e.g., Assembly-Data, International Barcode of Life) and provide standardized metadata beyond what source modifiers cover.

**TBL (Five-column feature table)**
:   A tab-delimited file describing sequence features (genes, CDS, mRNA, etc.) in NCBI's five-column format. Columns specify start position, end position, feature type, qualifier key, and qualifier value. Used by `table2asn` alongside the FSA file.

**GFF (General Feature Format)**
:   A standard tab-delimited format for describing genomic features. TOSTADAS uses GFF files as intermediate annotation output from Liftoff and VADR, which are then converted to TBL format for GenBank submission.

## Tools

**Bakta**
:   A tool for rapid annotation of bacterial genomes and plasmids. Produces GFF3, GenBank flat file, and other annotation formats.

**Liftoff**
:   A tool that maps annotations from a reference genome to a target genome. Used with RepeatMasker for poxvirus annotation.

**Nextflow**
:   A workflow management system used to build and run the TOSTADAS pipeline. Handles job scheduling, containerization, and pipeline orchestration.

**RepeatMasker**
:   A tool for identifying and annotating repetitive elements in genomic sequences. Used in the Liftoff annotation pathway for poxvirus genomes.

**table2asn**
:   An NCBI command-line tool that converts a FASTA file, feature table, and source modifiers into an ASN.1 Sequin file (.sqn) for GenBank submission. It validates the input data and reports errors in the generated output.

**VADR (Viral Annotation DefineR)**
:   A tool developed by NCBI for validating and annotating viral sequences using covariance models. VADR checks sequences against reference models, identifies features, and flags potential problems (alerts). Sequences must pass VADR validation to be accepted by GenBank.

## Submission Concepts

**FTP / SFTP (File Transfer Protocol)**
:   Protocols used to upload submission files to NCBI servers. FTP is the default method; SFTP (SSH-based file transfer) is available as an alternative when firewalls block FTP traffic on port 21. Configure with `--submission_mode ftp` or `--submission_mode sftp`.

**dry_run**
:   A test mode that prepares all submission files without uploading them to NCBI. Enabled with `--dry_run true`. Use this to verify that the pipeline generates correct output before performing a real submission.

**batch_size**
:   The number of samples grouped into a single submission package. Controlled with `--batch_size`. NCBI recommends batch submissions over individual sample submissions. A batch size of 25--50 is typical.

**BioSample package**
:   A predefined set of metadata attributes required by NCBI for a specific sample type (e.g., Pathogen.cl.1.0 for clinical pathogens, SARS-CoV-2.wwsurv.1.0 for wastewater surveillance).

**center account**
:   An organizational account registered with NCBI for programmatic submissions via FTP/SFTP. Unlike personal NCBI accounts, center accounts are tied to an institution and are required for automated submission workflows. Credentials are configured in `submission_config.yaml`.

**WGS (Whole Genome Shotgun)**
:   Whole Genome Shotgun sequencing. A sequencing strategy that sequences the entire genome in fragments, which are then assembled computationally.
